# Sample emails, contract 1

These files are generated by `make samples` from the fixed inputs in
`tests/contract_samples.py`, by the same `compose_mail` the service uses. Never edit one by
hand. A test fails when the mail code's output differs from a sample by one byte, and the
contract checker is run over every one of them. All addresses are placeholders.

| Sample | Shows |
|---|---|
| `podcast-feed.eml` | A podcast with a `feed:` guid, a `published` date, an `apple_url`, a paragraph merged over 30 seconds, a speaker change, and two lines of instructions |
| `podcast-feed.resend.eml` | A resend of the first sample: the same `Message-ID` and `job_id`, only `Date` differs |
| `podcast-feed.reshare.eml` | A re-share: the same `guid` and an identical note, with a new `job_id` and new instructions |
| `podcast-feed.retranscription.eml` | A re-transcription: the same `guid` with a different `transcript_sha256` |
| `podcast-apple.eml` | A podcast with an `apple:` guid, a date-only `published`, no `language`, and UTC offsets |
| `upload.eml` | An upload: a `sha256:` guid, the title from the file stem, no `published`, the date from `shared_at` |
| `direct-url.eml` | A direct URL: a `sha256:` guid and a `source_url` |
| `direct-url-query.eml` | A direct URL with a query: `source_url` is omitted and the title comes from the last path segment |
| `empty-instructions.eml` | An instructions file with an empty body |
| `hostile-title.eml` | A hostile title and show: sanitising, the 200-character title cap, the 120-character encoded subject, the `apple:` fallback for a guid that is not verbatim, and instructions that stay inert |
